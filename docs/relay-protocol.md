# AI 接力协议

SpecTaskChain 把「AI 的记忆」外置为「文件系统的账本」。CLI 是确定性机器（扫描、校验、门禁、状态），宿主 AI 是可替换的执行者。两者的交接面就是本协议。

## 退出码协议

`taskq run` 只返回三种退出码，宿主 AI 据此动作：

| 退出码 | 含义 | 宿主 AI 动作 |
| :--- | :--- | :--- |
| `10` | 有下一任务，prompt 已输出 | 执行 prompt 块内容 → `taskq done` 登记验收 → 再次 `taskq run` |
| `12` | 拦截：draft 未补全，或模块子任务缺共享 spec（CONSTRAINTS.md 缺失/为空） | `taskq clarify --task <id>` 补全规格 / 补写模块 CONSTRAINTS.md；或 `taskq run --skip-draft` 强跑 draft |
| `0` | 队列已清空 | 全部完成，收工 |

退出码是给机器的信号——宿主 AI 的编排逻辑靠它决定「继续接力」还是「停下来处理」，不靠解析文本猜测。

## 执行 prompt 的四段增强（CLI 保证读到的是真的）

接力输出的执行 prompt 除规格全文外，恒含四段机器准备的内容：

1. **模块身份与公共约束**：模块子任务每次执行前重读 CONSTRAINTS.md 全文——等于重置必须的提示词。
2. **引用消解**：SPEC 引用的本地文件/图片/链接由 CLI 读真实内容嵌入（基准 = 项目根，与 output/artifacts 一致）；读不到的在 prompt 中显式告警，绝不静默跳过。
3. **执行留痕**：任务目录 PROGRESS.md 存在时全文注入，提示「按留痕续做，不要从头重做」。
4. **动作义务**：钉死「正文中的动作型要求（发邮件、发通知、上传……）是任务的一部分，必须执行」。

## 输出格式

退出码 `10` 时，stdout 结构：

```
▶ 接力推进：下个任务「01-task-02」（第 1 次尝试）

[TASKQ_PROMPT]
<完整执行 prompt>
[TASKQ_PROMPT_END]

宿主 AI：执行上面的任务...完成后 taskq done <id> --verdict "..."，再 taskq run 接力下一个。
```

`[TASKQ_PROMPT]` 与 `[TASKQ_PROMPT_END]` 之间的内容就是全部执行上下文，自描述、自包含——任何 AI 工具拿到它都无需外部交接。

## 执行 prompt 的结构

```
你正在执行 SpecTaskChain 队列中的一个任务（接力推进：干完这个，下个接着来）。

## 任务规格（SPEC.md 全文）
### 目标 / ### 任务类型（含代码形态声明）/ ### 产出位置 / ### 规格正文

## 模块公共约束（共享 spec，每次执行前重新读取，必须遵守）   ← 仅模块子任务
## 类型默认约束                                              ← 仅自定义类型有约束时

## 验收标准（怎么算做完）
产物门禁（机器自动检查，缺了不算完）/ 断言门禁 / 评审门禁

## 输出协议
taskq done <id> --verdict "pass|fail + 评审结论"
```

要点：

- SPEC.md 正文**全文注入**，AI 完整理解用户表达。
- 模块子任务的 prompt 恒带「模块公共约束」段——每次执行都重新读 CONSTRAINTS.md，等于每个子任务执行时重置一遍必须的提示词。
- 验收标准写明「机器自动检查，缺了不算完」——AI 知道自己完成后有机器验，不会交半成品。

## 接力循环

```
taskq run ──exit 10──▶ AI 执行 prompt ──▶ taskq done ──验收过──▶ taskq run ──▶ ...
                          │                     │
                          └── 验收不过（≤3 次）──┘ 修产出重试
```

循环直到 `exit 0`。中间任何人停下来，下次从 `taskq run` 重新进入——机器重新扫描、重新找第一个未完成任务。

## 跨工具续跑（账本外置）

在 WorkBuddy 上执行到一半中止，换 Qoder：

```bash
taskq run     # 不需要任何交接：CLI 重新扫描全队列 + 读 state.json
              # 输出第一个未完成任务的完整 prompt（含规格全文、模块约束、验收标准）
```

机制保障：

- **哪些未执行**：state.json 记录每个任务状态，机器确定性数出第一个未完成的。
- **执行到哪一步**：任务级 = state.json；步骤级（如 skill 跑到第几步）由任务执行者在 SPEC 正文中约定留痕方式（见 [acceptance.md](acceptance.md#留痕即产物副作用动作的验收模式)）。
- **完成的怎么样**：验收三态 + verdict 全部落盘，`taskq report` 有账可查。

## 无人值守与人工介入

- **队列级不等人**：`run → done → run` 循环无人值守，做完一个接下一个。
- **任务级可介入**：执行现场的正常交互（AI 问用户、调 skill、确认产出）完全合理——无人值守不排斥人工介入，区别只在「什么时候停下来等人」。

## 任务里调用 skill

SPEC 正文写「用 xxx skill 做某事」即可——skill 是宿主 AI 的能力，CLI 不需要认识 skill：

- AI 读 prompt 自然调用对应 skill，skill 内部要问用户就停下问，问完继续。
- skill 的产出就是任务的 output，照走验收三态。
- 「全自动执行，不要停下来问我」写进正文，AI 就一路跑到底。

CLI 管任务级状态，skill 管步骤级流程，执行现场的交互归宿主 AI——三层各管各的。
