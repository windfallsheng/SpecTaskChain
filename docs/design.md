# 设计决策与路线图

SpecTaskChain 的核心命题：**脱离具体使用哪个 agent 工具进行开发**。每一处设计都从「账本在文件里，AI 是可替换的执行者」推演而来。

## 设计决策

### 队列是第一公民，链 = 接力不是依赖

一次建一堆任务、无人值守接力完成，是这个工具的立身场景。「链」不是依赖环——多数任务之间没有依赖关系，依赖是少数任务的可选声明。共享上下文（任务模块）、执行顺序（依赖声明）、接力完成（队列本身）三种关系正交，不互相绑架。

### 规格与状态是唯一事实源

- SPEC.md（规格）+ state.json（状态）+ 产出文件（成果）全部落盘在队列里。
- 跨工具续跑零迁移：换 IDE、换 AI 工具，`taskq run` 重新扫描 + 读状态，机器确定性找到第一个未完成任务，输出自包含的完整 prompt。
- 任何 AI 的「记忆」都不可靠（会话断、工具间不互通），文件不会变。

### CLI 是确定性机器，不做外部副作用

CLI 只做扫描、校验、门禁、状态。发邮件、发通知、上传这类动作由宿主 AI 执行，机器负责给每一次副作用留字据（留痕即产物，见 [acceptance.md](acceptance.md)）。确定性机器不做不确定的事，不确定的事交给有判断力的执行者。

### 验收先行：怎么算做完是必填第一公民

三态门禁（产物/断言/评审）挂在任务上，`taskq done` 当场查验。机器能查的（文件在不在、命令通不通）硬门禁，机器查不了的（结构、风格）软门禁。没有验收的任务不配无人值守——AI 交付标准靠猜，队列就成了聊天清单。

### draft 拦截：规格不完整，宁可停不可裸奔

新任务恒定 draft 起步，`taskq run` 对 draft 返回退出码 12 拦截。让「补全规格」成为显式动作，而不是执行时 AI 的临场发挥。

### 非代码类型默认与代码世界绝缘

任务类型默认不写代码，显式声明 `code: true` 才切代码形态。写文档、整数据、做调研的任务零配置即可跑；写代码是显式选择，不是默认假设。

### 澄清是用户自己的操作行为

系统只提供入口、检测和报告，从不打断执行。随叫随到的体检，处理四式（补 / 给默认值 / 标记 draft / 无视）全在用户手里——机器不替用户做决定。

## 三层分工

| 层 | 职责 | 例子 |
| :--- | :--- | :--- |
| CLI（确定性机器） | 扫描、校验、门禁、状态、prompt 组装 | `taskq run/done/clarify/status` |
| 宿主 AI（可替换执行者） | 执行任务、调 skill、写产出、执行动作 | 写文档、发邮件、跑测试 |
| Skill（宿主 AI 的能力） | 任务执行中调用的一串工作流程 | md→HTML→截图 |

任务里写「用 xxx skill 做某事」，AI 读 prompt 自然调用。CLI 管任务级状态，skill 管步骤级流程，执行现场的交互归宿主 AI。

## 路线图

以下能力已全部实装（v0.1.0 首版）：

1. **`taskq split` 文档拆任务**：从一份文档/一段文字拆分出任务草案（名称、目录、初步内容），中间反复确认，最后逐个完善 spec。边界：拆分只产出 goal 和初步内容，不碰验收三态。
2. **引用消解**：SPEC 中引用的文件/图片/链接，由 CLI 读取真实内容嵌入 prompt——本地文件全文嵌入（基准 = 项目根），图片确认存在并给绝对路径，外部链接尝试抓取。读不到 = clarify 阻塞项 + prompt 显式告警，绝不静默跳过。
3. **模块约束加固**：模块 CONSTRAINTS.md 缺失或为空即阻塞执行（exit 12），绝不静默裸奔；子任务 prompt 恒带模块身份声明（属于哪个模块、第几个子任务）。
4. **执行留痕**：任务目录 PROGRESS.md 承载步骤级进度，断点续跑时全文注入 prompt——AI 先读留痕再决定续做还是重做。
5. **动作要求执行义务**：执行 prompt 模板钉死「正文中的动作型要求（发邮件、发通知、上传……）是任务的一部分，必须执行」，与「引用内容必须执行」同性质。
