# 澄清体检

澄清是**用户自己的操作行为**：系统只提供入口、检测和报告，从不打断执行。随叫随到的体检，处理权在你。

## 四个入口

| 入口 | 场景 | 命令 |
| :--- | :--- | :--- |
| 写完查 | 刚写完/改完规格，查单个任务 | `taskq clarify --task <id>` |
| 建链查 | 建完整个队列，查链级硬伤（依赖、冲突、循环） | `taskq clarify --chain` |
| 翻车查 | 执行翻车了，查全队列找病根 | `taskq clarify`（无参数） |
| 随口查 | 对话里随口一说 | `taskq ask "澄清一下"`（意图路由） |

`--file <路径>` 可体检任意 SPEC.md 文件（还没入队的也行）。

`--chain` 只查链级硬伤（依赖悬空 / 产出冲突 / 模块约束 / 命名重复 / 循环依赖），不逐任务报三必填——建链前任务可能还没写完；无参数则链级硬伤 + 各任务三必填全量体检。

## 四级信号

### ⛔ 阻塞（blocking）——必须处理

- 缺三必填：goal / output / acceptance（至少一项非空）
- 依赖悬空：`depends-on` 指向不存在的任务（覆盖顶层与模块子任务）
- 产出路径冲突：两个任务写同一位置
- 引用悬空：SPEC 引用的本地文件/图片不存在——执行时 AI 读不到真实内容（基准 = 项目根，与 output/artifacts 一致）
- 模块缺共享 spec：CONSTRAINTS.md 缺失或为空——子任务每次执行前都要重读它，缺了会阻塞接力
- 共享 spec 内容级体检：与子任务同权——共享约束里的模糊词/指代不明 → 建议档；可执行性风险 → 方案菜单（含糊写进共享底座会被所有子任务继承放大，更该查）
- 跨层 ID 重复：子任务 ID 与顶层任务撞车——任务 ID 是 state.json 的键，跨层重复会共享状态，请改名区分

### ⚠️ 建议（suggest）——建议处理

- 验收只有评审门禁（review）：无人值守没有机器可查的地基
- 模糊词：做好、完善、优化一下、适当、尽量、差不多、相关、一些——不可验收，AI 交付标准靠猜
- 指代不明：那几个、相关资料、这些文件、那些东西、那个文件——执行时 AI 只能脑补所指
- 命名可读性：目录名是随机占位（t+时间戳）或含非 ASCII——建议 ASCII slug 作目录名、中文显示名写 name 字段
- 命名重复：同层任务 slug 撞名——清单浏览时分不清谁是谁，建议区分
- 循环依赖：depends-on 成环——不阻断执行（环成员按原序号平铺接力），但依赖关系已失效，建议打破依赖环
- 角色未定义：SPEC 的 `role` 指向不存在的角色（内置无、`.taskchain/ROLES/` 也无）——执行时按无角色处理，建议补建角色文件或删掉该字段
- 未指定角色：SPEC 无 `role` 字段——执行时 AI 按任务内容自动选择最专业的角色（类型建议可推翻）；要固定就补 `role` 字段

### ⏳ 待定（pending）——按节奏处理

- `draft: true` 标记：规格未补全，执行前建议先补

### 🤖 可执行性风险（exec）——AI 能力圈的边界，亮出方案菜单做人机分工

规格写得再完整，任务本身超出 AI 的能力圈，接力就是空转。体检会扫 goal 与正文，命中以下信号就亮出来（确定性词表，零成本），**每条自带 2-3 个可选方案，各带评分（10 分制）与唯一 ✅ 推荐方案（附推荐理由）**，覆盖三条出路：

1. **改什么 AI 就能做**——补齐 AI 缺的凭据/权限/数字化通道
2. **换什么内容 AI 能做**——换成 AI 可执行、可验证的产出
3. **人机分工**——AI 做闸口内的事（材料/脚本/清单），人做闸口外的事（认证/审批/物理动作）

| 类别 | 触发信号（例） | 风险本质 | 方案菜单 |
| :--- | :--- | :--- | :--- |
| 认证凭据 | 登录、扫码、验证码、人脸识别、指纹、U盾 | AI 无账号、无生物凭证、收不到验证码 | ①补测试凭据（人提供测试账号/固定验证码） ②换自动化通道（API token 绕开交互认证） ③AI 做到闸口，认证由人 |
| 权限审批 | 审批、管理员权限、root、内部系统、OA | AI 无权限，也不能替人审批 | ①划权限边界（开发环境专用账号/白名单） ②换验证环境（沙箱/mock 验证后再走审批） ③AI 备料人审批 |
| 物理动作 | 邮寄、盖章、签字、插拔、真机 | 物理动作 AI 没有手 | ①换数字化替代（电子签章/云打印） ②砍掉物理环节（改电子版产出） ③AI 备料人跑腿 |
| 平台账号 | 公众号后台、应用商店、企业微信后台 | AI 无第三方平台账号 | ①补自动化凭据（开放平台 API/密钥走接口） ②换验收方式（AI 出内容人发布，截图留痕） ③AI 备料人发布 |
| 资金合规 | 付款、报销、合同签署、投标 | AI 不能也不该直接执行 | ①换验证环境（沙箱/测试通道支付） ②砍成准备态（AI 只做材料，资金动作另立任务） ③AI 备料人审批，凭证留痕 |
| 外部等待 | 等审批通过、等对方回复 | 依赖外部响应，AI 只能到闸口 | ①改触发条件（邮件主题过滤/状态接口轮询可自动判断） ②换执行时机（改待命态，人标记后 AI 接力） ③AI 备模板人跟进 |

- 每条方案标明了**谁来做**：🤖 AI 可执行 / 👤 人来完成 / 🤝 人机协作（终端与 CLARIFY.html 均展示）。
- 每条方案带**评分（10 分制）**，推荐方案置顶并附**推荐理由**——用户做判断题（采纳 / 换方案 / 跳过），不是选择题。
- 定位是**提示档，不拦接力**：亮风险 + 方案菜单，选哪条由用户定。
- 判断题通道：`taskq clarify --task <id> --decide` 逐项裁决（y 采纳当前方案 / n 换下一个方案 / s 跳过）；采纳写回 SPEC.md frontmatter `decisions` 留痕，下次体检自动跳过已决信号。
- 仍可四选一处理（改规格把动作拆出去 / 给默认值 / 标 draft / 无视）。

## 处理四式（可执行性风险另有第五式）

体检报告不替你做决定，几条路自己选：

1. **补**：改 SPEC.md，把缺的、模糊的补上。
2. **给默认值**：不吭声，执行时按默认理解走（自己心里有数）。
3. **标记 draft**：先占坑，执行前再补（`taskq run` 会拦截 draft 提醒你）。
4. **无视**：自己的队列自己负责，建议项不强制。
5. **判断题裁决**（可执行性风险专属）：`taskq clarify --task <id> --decide` 逐项做判断题——每条方案带评分（10 分制），推荐方案置顶附理由，y 采纳 / n 换方案 / s 跳过；采纳写回 SPEC.md 的 `decisions`（下次体检跳过已决信号），AI 就能继续执行。

## 与执行的关系

- `taskq run` 对 draft 任务返回退出码 `12` 拦截（不静默执行规格不完整的任务），`--skip-draft` 强跑。
- 澄清从不阻断其他任务：队列接力照常，体检是旁路行为。
