# 验收三态门禁

规格驱动队列与所有「AI 任务清单」的分水岭：**怎么算做完，是必填第一公民，且由机器当场查验**。

`taskq done <task-id> --verdict "..."` 触发三态门禁：

| 门禁 | 检查方式 | 执行者 | 性质 |
| :--- | :--- | :--- | :--- |
| 产物门禁 | 文件存在且非空 | CLI（glob 匹配） | 硬门禁 |
| 断言门禁 | shell 命令退出码 0 | CLI（execSync） | 硬门禁 |
| 评审门禁 | AI 审查结论 | 宿主 AI 传 verdict | 软门禁 |

三态全过才登记 done；任一不过，尝试次数 +1（上限 3 次），修正后重试。

## 产物门禁（artifacts）

```yaml
acceptance:
  artifacts:
    - path: docs/migration-*.md   # glob 风格，* 不跨目录
      min: 3                      # 最少命中数（缺省 1）
```

规则：

- 路径基准 = **项目根**（`output` 是用户视角路径，AI 也在项目根干活）。
- `*` 通配不跨目录；命中文件必须**非空**（0 字节不算）。
- `min` 支持批量产物（如「3 篇文档」）；目录下文件数与规则一一对应可验。
- 以 `~` 结尾的临时文件不计入。

## 断言门禁（checks）

```yaml
acceptance:
  checks:
    - grep -q '订单表' docs/migration-order.md
    - test -f reports/.sent-marker.txt
```

规则：

- 工作目录 = 项目根，超时 30 秒，退出码 0 才算过。
- 命令输出捕获，失败时展示前 200 字符——机器告诉你**为什么**没过。
- 断言命令里不要带字面双引号包裹整条命令（会被 shell 当命令名），例如写 `grep -q '迁移' docs/migration-01.md` 而不是 `"grep -q '迁移' docs/migration-01.md"`。引号用于参数内部没问题。

## 评审门禁（review）

```yaml
acceptance:
  review: 三篇文档结构一致，字段映射准确
```

- 软门禁：AI 按 review 标准自我审查，结论随 `--verdict` 传入；verdict 含 `pass` 或「通过」即过。
- review 为空 = 不启用评审门禁。
- **设计原则**：评审门禁只适合机器确实查不了的东西（结构、风格、完整性判断）。无人值守的地基是产物 + 断言——只有软门禁的任务，clarify 会建议补硬门禁。

## 留痕即产物（副作用动作的验收模式）

任务不止「写东西」，还有「干事情」：发邮件、发通知、上传、调用外部服务。这类**副作用动作**的验收原则：

> 副作用必须有留痕，留痕即产物。

```
写 PPT → 发邮件给张总 → 写 .sent-marker.txt（收件人/时间/主题）→ 通知用户
            ↑副作用              ↑留痕进产物门禁              ↑写进正文，AI 执行时汇报
```

- CLI 自己不发邮件、不发通知（确定性机器不做外部副作用），执行者是宿主 AI。
- 验收不重放副作用（邮件不能重发），而是验留痕：`.sent-marker.txt` 存在 + grep 收件人对得上。
- 动作没做成，失败可见：留痕没落盘 → 门禁不过 → 任务 attempts +1 → 最多 3 次标记 failed → `taskq report` 里看得见「这个任务翻在发邮件上」。

## 失败重试语义

```
taskq done 验收失败
  ├─ attempts < 3 → 标记 failed，修正产出后重试 taskq done
  └─ attempts ≥ 3 → 标记 failed（attempts 上限）
```

- failed 的任务不会被永久踢出：`taskq run` 仍会重新拾起它（修复是人工介入的活，机器不放弃）。
- 每次 `taskq done` 都全量重跑门禁——产物删了重做、断言修了重验，账上刷新。

## 设计验收的几条建议

1. **产物优先**：能写成「文件存在」的就用产物门禁，这是最硬的地基。
2. **断言查内容**：文件在 ≠ 内容对，grep/测试命令补内容级检查。
3. **副作用必留痕**：动作型要求配留痕文件，别让验收无字可查。
4. **评审兜底**：机器实在查不了的判断交给 review，但别只留它一个。
